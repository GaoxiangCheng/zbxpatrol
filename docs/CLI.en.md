## 1. Install & configuration

Single binary, no runtime deps. `chmod +x` anywhere (artifacts in `dist/`: Linux x86_64/aarch64 musl static, macOS arm64).

**Three config layers (high → low priority, never overridden by lower ones)**:

1. Process env vars: `ZBX_URL` / `ZBX_USER` / `ZBX_PASSWORD` (required); optional `ZBX_TIMEOUT`(30s), `ZBX_INSECURE`(false), `ZBX_TZ`(Asia/Shanghai), `PATROL_CONCURRENCY`(8), `PATROL_RATE_LIMIT`(10/s);
2. `./.env` in the working directory (project/deploy level);
3. `~/.zbxpatrol/config.env` (generated by interactive setup, mode 600).

> First run in a terminal walks you through setup and writes layer 3; non-interactive runs exit with code 2 when config is missing — they never hang.

<a id="global"></a>
## 2. Global flags & exit codes

| Flag | Description |
|---|---|
| `--format table\|json\|csv` | Output format (default table; json/csv for programs — data on stdout) |
| `--quiet` | Silent (no progress) |
| `--no-interactive` | Disable interaction (automatic when not a TTY) |
| `--verbose` | Debug logs (logs always on stderr) |
| `-h/--help` | Help with examples per subcommand (angle brackets = variables) |

**Exit codes**: `0` OK · `2` config/credentials · `3` network/API · `4` partial data missing (report still complete).

## 3. Subcommands

<a id="check"></a>
### 3.1 check — connectivity/credentials/permission self-check

```bash
zbxpatrol check
```
Verifies reachability (hints ZBX_INSECURE on cert issues) → login → read permission, ✓/✗ per step.

<a id="groups"></a>
### 3.2 groups — list groups

```bash
zbxpatrol groups [--search <substr>] [--page N] [--size N]
```
`--search` name filter; `--page` (1-based, default 1) + `--size` pagination (`--size` alone = page 1).

<a id="hosts"></a>
<a id="items"></a>
### 3.3 items — item catalog

```bash
zbxpatrol items [--host <host>|--group <group>] [--search <substr>] [--detail]
```
Aggregated by key (key/name/unit/type/host-count) by default; `--detail` (with `--host`) lists rows incl. current values.

<a id="query"></a>
### 3.4 query — stats for arbitrary items

```bash
zbxpatrol query --key <K> [--key <K2>…] [scope] [time] [--csv <file>] [--chart] [--format json]
```
- keys support `*` wildcards (e.g. `net.if*`); repeat `--key` or comma-separate;
- `--chart`: after the table, appends a full-size trend plot (72 buckets, Y scale + avg line) for the **single matched** series; with multiple series matched it exits with code 2 asking to narrow via `--host`/exact `--key`; mutually exclusive with `--format json/csv`;
- outputs cur/avg/max/min + **trend sparkline** (when ≤30 items matched);
- `--csv` saves a CSV (UTF-8 BOM, opens in Excel).

<a id="chart"></a>
### 3.5 chart — single-host trend chart (ASCII)

```bash
zbxpatrol chart --host <host> --metric cpu|mem|disk [time]
zbxpatrol chart --host <host> --key <item-key-or-wildcard> [time]   # any item; wildcard must match exactly one
```
Y-axis scale, average dotted line, time axis, min/avg/max summary; `--format json` returns the series.

<a id="report"></a>
### 3.6 report — inspection report (core)

```bash
zbxpatrol report [scope] [time] [--strictness loose|standard|strict]
                 [--keys <k1,k2,…>] [--all-items]
                 [--data-json <file>] [--out <dir>] [--config patrol.toml]
```
- Scope: `--group` (repeatable) / `--host` / `--hosts a,b,c` (default all hosts);
- Time: see [section 4](#time);
- `--strictness`: loose (baseline 90%) / standard (80%) / strict (70%);
- `--keys`: extra custom items (wildcards ok) → Excel "custom items" sheet + JSON `extra`;
- `--all-items`: attach a sheet with all numeric items;
- Output: xlsx (`巡检报告_<from>-<to>_<scope>.xlsx`, conditional coloring) + console color table (default with `--format table`); `--format csv` prints flat CSV; `--data-json` saves structured JSON.

<a id="serve"></a>
### 3.7 serve — local HTTP API

```bash
zbxpatrol serve --listen 127.0.0.1:8787 [--token <TOKEN>]
```
See the [API doc](API.en.md).

<a id="completions"></a>
### 3.8 completions — emit shell completion

```bash
zbxpatrol completions bash | sudo tee /etc/bash_completion.d/zbxpatrol
source <(zbxpatrol completions bash)      # session-only
zbxpatrol completions zsh > ~/.zfunc/_zbxpatrol
```

<a id="dunder"></a>
### 3.9 __complete (hidden) — completion data source

```bash
zbxpatrol __complete groups                # group names
zbxpatrol __complete hosts                 # host names
zbxpatrol __complete items --host <host>   # numeric item keys of the host
```
Used by the completion scripts; silent (empty output) on failure.

## 4. Time parameters (pick one, priority high → low)

```bash
--from "2026-09-01[ 08:00:00]" [--to "…"]   # absolute (to default = now)
--last 48h|15d|12M|30m                       # relative duration
--period day|week|month|year                 # preset (default day)
```

<a id="scope"></a>
### Scope & wildcards

- `--group <group>` repeatable; `--host <host>` single; `--hosts a,b,c` multi; default all hosts;
- key wildcard: `*` any segment (`vfs.fs*pused*`), case-sensitive; host names must match Zabbix exactly (completion avoids typos).

## 5. Shell completion (multi-level Tab)

After installing [3.9](#completions):

| Stage | Tab result |
|---|---|
| `zbxpatrol <TAB>` | subcommands (prefix-filtered) |
| `zbxpatrol items <TAB>` | all options of that subcommand |
| `items --group <TAB>` | **real group names** from Zabbix |
| `--group <value> <TAB>` | remaining options (keeps going) |
| `chart --host <host> --key <TAB>` | **real item keys of that host** (prefix-filtered) |
| `--metric/--period/--strictness/--format <TAB>` | enum values |

## 6. Scheduling & deployment

